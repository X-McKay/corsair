# Corsair evaluation-gym loop

One wave, driven by CLI exit codes so no harness reproduces a judgment. Design and rules: [PLAN-0003](../../../docs/plans/active/PLAN-0003-evaluation-gym.md), [AGENTS.md](../../../AGENTS.md), [evaluation rules](../corsair-evaluations/SKILL.md). Toolchain is `nix develop -c just …` from a synced worktree; live settings are `.state/settings.json` on the `hosted_vllm/` route; gym runs use the Temporal namespace `corsair-gym` and never `default`.

## Roles

- **Orchestrator** (one per wave): writes briefs, runs gates, merges, captures fixtures, appends the ledger. Only this role writes `evals/experiments/ledger.jsonl`, `LEDGER.md` and the plan record.
- **Auditor** (read/run only): runs tiers, clusters `failure_stops`, proposes 2 to 3 hypotheses with disjoint file scopes after checking the rejected table. The only role besides the orchestrator that sees tier2 (holdout) per-case results.
- **Experimenter** (one per hypothesis, own worktree cut from the integration branch): one bounded change in its exclusive file scope; never edits oracles, fixtures, manifests, budgets, the ledger or the plan; never sees tier2.
- **Case miner** (separate wave from prompt tuning): proposes `request.json` and `Oracle` files through intake; the owner reviews every oracle before it is frozen into a tier. `dataset freeze` writes the review record (`corsair.dataset-review/1`: decisions, reviewers, reasons, frozen oracle digests) to `evals/datasets/reviews/<manifest stem>/`; commit it with the manifest, since the sheet stays in the ignored draft directory. A stand-in reviewer writes `pending owner audit` in the reviewer column, and `just dataset-audit` lists those rows (and `unreviewed` ones) for the owner. Remove a case miner's worktree only after its review record is tracked on the integration branch ([guide](../../../docs/guides/evaluation-gym.md#review-records-and-the-audit)).

## Wave

1. Reference. If the ledger has no reference row for the integration HEAD, run from a detached worktree of that commit that nothing else edits (`git worktree add --detach .worktrees/gym/ref-<sha> <sha>`, then `nix develop -c just sync` there; never merge into a worktree with a live run): `just -- gym-run tier0 --repeats 3` and `just -- gym-run tier1 --repeats 3`; copy their scorecards to `<main checkout>/.runs/gym/reference/tier0.json` and `tier1.json`; `just -- gym-ledger append --kind reference …`. The reference settings' `models.decoding` block (temperature, top_p, seed per role; unset means server default) is part of the recorded configuration identity, so a candidate at other decoding gates against a different configuration; `corsair doctor --model` prints it.
2. Diagnose. Auditor returns failure clusters by kind and gate, token and time outliers (`corsair gym replay RUN CASE`), and hypotheses `{id, track, target metric, mechanism, files}` with pairwise-disjoint files.
3. Experiment. Per hypothesis, in its worktree: `nix develop -c just sync`, failing test first, change, `just test`, `just check`, plus `just test-docker` for sandbox/driver/image scopes and `just test-temporal` for workflow scopes; then `just -- gym-verify <reference> --noise <reference>/noise-tier1.json` (tier0 run and gate, tier1 run and gate unless tier0 is REJECTED; last line `VERDICT: …`, exit 0/1/2/3, `verdict.json` beside the shared runs). Runs land in the shared gym root `<main checkout>/.runs/gym/` (`just -- gym-runs` lists them), so they survive worktree removal. Live runs serialise automatically: `gym run` and `gym verify` take the gym root's run lock (`verify` once for both tiers) and wait while another live run holds it, logging the holder every minute up to `--lock-timeout` (default 2 h, then exit 2); there is no marker file to wait for. `corsair gym lock status` names the holder; `--no-lock` is for scripted tests only. The worktree stays untouched (no commit, merge or branch switch, by anyone) from the start of `gym-verify` until its `VERDICT:` line: a run pins its manifest (`dataset.json`) and its finish imports, and `gym runs` marks a run whose commit changed before it finished; re-run such a run instead of gating it. Commit as `exp(<id>): <summary>`; return branch, commit, both gate tables and the verdict path, commands with counts, identity change, unrun gates.
4. Gate. `corsair gym gate --baseline REF --candidate CAND --track accuracy|efficiency|objective [--target-language L] --noise <gym root>/reference/noise-<tier>.json` (or `corsair gym verify --track … --noise …`) on the hypothesis's track: exit 0 ACCEPTED, 1 REJECTED, 2 INCOMPARABLE, 3 INCONCLUSIVE. From wave 4 on, gate tier1 with `--min-cases 3 --noise <gym root>/reference/noise-tier1.json` (`gym verify --min-cases 3 --noise …` applies it to tier1 only): only languages with at least three reference cases decide `language_regressed` and the accuracy criteria, the single-case languages are shown as `reported only`, and the gate prints the paired per-case table (`pass_to_fail`, `fail_to_pass` and the flipped case ids; `paired_regression` rejects an otherwise accepted gate whose deciding cases fell more than they rose). Report the paired table with the verdict; J is still reported on all languages. Noise rule: gate with the reference configuration's band (`just -- gym-noise REF-RUN REPEAT-RUN` after a second reference run; measure a new band when the reference changes identity). With the band an improvement counts only beyond it, and when every deciding regression lies inside it the gate is INCONCLUSIVE: run one confirmation run of the same candidate commit and gate it against the same reference and band; ACCEPTED or REJECTED decides, a second INCONCLUSIVE is recorded `inconclusive` and not merged. Never pool the confirmation run with the first or add it to the band. A regression in a single-case language is labelled `single case`: one episode, read it as such. Every track needs no language regression. Accuracy: macro verified accuracy up by at least one case's majority in the largest language (1 / (languages × its cases), 1/66 on tier1 with 11 python cases), or the target language up, and tokens ≤ 1.10×. Efficiency: macro verified accuracy ≥ baseline and macro effective tokens or p50 seconds ≤ 0.90× (seconds only at equal concurrency with no operational episodes, else `latency_not_comparable`). Objective (default): J +0.01 and tokens ≤ 1.10×; J is always reported and is the overall objective and tiebreak.
5. Integrate. Merge accepted branches `--no-ff` into the integration branch one at a time, re-gating each later branch against the new HEAD; re-run tier0 on HEAD and record it as the new reference. Remove rejected worktrees after logging the lesson.
6. Capture and record. `just -- gym-capture RUN CASE` for every failed or flipped case (fixtures are the fast, model-free guard); `just -- gym-ledger append …` per experiment; `just -- gym-ledger render`; append commands and outcomes to the plan record, naming what was unrun.

## Invariants

- A live run executes from a checkout nothing else edits; `gym score` and `gym capture` read the run's pinned `dataset.json` and refuse a `--dataset` of another digest (`dataset_mismatch`, exit 2).
- Same dataset digest, budgets digest and repeats on both sides of a gate; anything else is INCOMPARABLE, never a win or a regression.
- Any prompt, packet-builder or tool-declaration, schema, budget, driver, image or model change is a new configuration identity (a packet-builder change shows as `producer_packet`/`auditor_packet` in the gate's `Identity changes:` line); say so in the ledger row.
- Missing usage stays unknown; ERROR, UNABLE_TO_RUN and INCONCLUSIVE are never negatives; a failed reproduction never yields EXPLOIT_NOT_DEMONSTRATED.
- No second agent loop, scheduler, tracing stack or replay engine; no model-authored execution; no oracle or outcome in agent, tool or workflow inputs.
- One shared model endpoint: compare latency at equal concurrency; `cpu_seconds` is the contention-resistant figure.
- Nothing is promoted and nothing is pushed without the owner's instruction.
