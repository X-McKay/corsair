# Corsair development instructions

Follow current user authorization. Corsair verifies security findings with two ADK agents over a deterministic, coverage-gated kernel on Temporal. Read README.md, docs/index.md and docs/plans/README.md before work. Preserve unrelated changes and inspect the branch/status.

## Ownership and organization

Google ADK owns agent execution; Temporal owns durable coordination. Workflows must perform no filesystem, model, network or Docker I/O. Ordinary activities own those boundaries. Private factories, instructions, declarative metadata, toolsets, source tools and runtime procedural skills stay under agents/<role>. Role-local contracts.py re-exports canonical class objects, never schema copies. Canonical Pydantic contracts live once in contracts/ and are publicly re-exported. Domain-only ports/ defines inference, admitted source snapshots and sandbox execution; actual SDK implementations live under adapters/. CLI, typed Python API and explicit worker composition belong in entrypoints/; verification/activity orchestration in steps/, pure decisions in policies/, evaluator logic in evaluation/ and logs in observability/.

Use installed, pinned native SDK APIs first. Agents declare their canonical Pydantic output_schema directly; do not reintroduce string-to-object repair, custom submit state or duplicate schemas. Do not implement a second agent loop, graph, scheduler, retry broker, tracing stack or checkpoint engine. The investigation result converges on one canonical per-round record (candidate payload identity, bound operation id, audit decision and rule, coverage, evidence scope, completion) by adding fields to the existing sessions and rounds, never by running a parallel protocol beside them. Keep concrete composition: no empty provider modules, registries or backends without implemented behavior. Remote forge and Bedrock-specific adapters are not qualified merely because their filenames are proposed. Runtime resources must be loaded from the built package, not the checkout working directory. Development skills belong under .agents/skills; runtime skills belong under the relevant agents/<role>/skills/. Native procedural loaders may expose reviewed packaged instruction/reference text only; no scripts, code executor, environment, remote registry or implicit permissions.

Evaluation assets have exactly datasets, evaluators, experiments, fixtures and baselines under evals/. Executable evaluators remain canonical installed package code; evals/evaluators documents their roles rather than duplicating them. tests/ has only unit, integration, workflow, replay and security directories, plus standard root package/pytest files. Put shared test helpers in their owning category and use ordinary imports; do not recreate a top-level tests/fixtures package or file-based fixture import loader. Generated bytecode and obsolete cache-only directories are not components.

## Evidence and security

The initial recipe admits JSON payload proposals, never model-authored execution/assertions. Only trusted evidence code can produce observations. Untrusted target code runs only in the configured Docker sandbox, never on the host. Keep source/tooling read-only, credentials/socket outside containers, network and resource limits enforced, and cleanup bound to immutable container identity.

Failed reproduction never permits a EXPLOIT_NOT_DEMONSTRATED / non-exploitable conclusion. A clean negative counts once per distinct exploit payload; a repeated candidate never adds independence, and clean negatives are admitted only for recipe kinds whose auditor rubric is qualified. Every verdict's evidence scope is the component seam the recipe drives; `result.scope` records the claim. Missing evidence, native reports, coverage, unexpected exceptions, provider errors, lost hosts, and uncertain completion must remain explicit. Scope is component unless an admitted application recipe proves otherwise. An outcome-blind auditor can veto semantic validity, not create factual evidence or authorize publication. Oracles never reach agent, tool or workflow inputs. Each recipe kind's violation condition belongs in reviewed, human-authored reference text that trusted code selects through the recipe discriminator; a kind without a qualified auditor rubric admits no clean negative. Audit rules are the enum R1 to R4 and ALL, and an incoherent decision/rule pair is an invalid audit. Human views print only code-owned text; model-authored reasons stay in machine output.

In-process observers cannot attest hostile source in any runtime; a C violation additionally requires the sanitizer's own exit status. Private state (.runs, .state, .work, .venv) and the configured artifact root are never admitted as source. Do not claim generic hostile-source observation integrity, exactly-once execution, full host-loss continuation, broad patch verification, or production readiness based on mocks or configuration. New recipes, permissions, languages, backend/runtime or model changes require affected conformance/evaluation and a new configuration identity.

## Development workflow

Implement a bounded component; test it and its consumers. Evaluate producer/auditor independently with genuine ADK and frozen fixture cases before calling composition qualified. Distinguish scripted, live-model fixture, real Docker, real Temporal and full live-chain results.

Before delivery: test end to end, review concrete boundaries, remove dead code/generated private artifacts, re-test, build the wheel, load its resources outside the checkout, and update the current plan/handoff with actual commands/results and failed/unrun gates. Publish only within user authorization. Never commit .runs, .state, credentials, private diagnostics or raw reasoning. Missing usage/cost stays unknown, not zero. A command that rewrites a frozen manifest exits non-zero and prints the old and new identities; a comparison across different datasets is INCOMPARABLE, never a regression verdict.

Use `just check` before delivery: pinned Ruff lint/format plus pinned ty and local documentation checks, with type warnings failing CI. No broad typing ignores. Frozen fixtures retain declared hashes/line numbers and are not Ruff style targets; typing and native conformance still cover them. Keep functions named for one ownership boundary and prefer concrete composition over speculative mixins. Treat dead-code scans as candidates: verify SDK callback/schema usage before deletion. Re-run the affected unit/native tests and a final frozen evaluation after refactoring; report narrow performance measurements without claiming overall agent speedup.

Developer tooling is provided by the one-input flake.nix/flake.lock shell on macOS arm64 and Linux amd64. Use `nix develop`, `just sync check`, and quoted literal task arguments. Keep platform admission capability-based and covered by actual host tests. Do not claim fully hermetic/bit-identical runtime builds or cross-platform native execution without corresponding gates. Preserve historical handoffs as exact records, not current command instructions.

Keep private/generated state, scratch, caches, credentials, local databases, tool metadata and delivery archives ignored and excluded from source packages. Use one root .venv; ongoing persistence/configuration lives under .state, complete immutable evidence under .runs and disposable or explicitly retained investigation material under .work. Migrate SQLite via verified backups, not blind moves; recreate virtualenvs. Do not prune unknown-operation claims or arbitrary artifact blobs.

Keep current guidance in the requested docs/getting-started, architecture, development, guides, operations, reference and agents sections. docs/index.md is the navigation hub; docs/plans/README.md is the current work index. Active plans/issues belong under docs/plans/active; completed plans, handoffs and reviews belong under docs/plans/archive. Historical records retain failures and their revision context; do not rewrite them into current qualification claims.

Root README is concise navigation. CONTRIBUTING, SECURITY, CHANGELOG and LICENSE are the policy entrypoints; never choose new licensing terms or invent release/security support promises without authorization. Configuration, API and schema references are grounded in source, not duplicate implementations. A documentation move must update relative links, preserve package risk references, validate documented commands and package the final working tree without caches, secrets or private evidence.
