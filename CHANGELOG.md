# Changelog

This file records released changes. It is not a declaration that the working tree has been committed, published or released. Implementation and qualification records live in [plans and archives](docs/plans/README.md).

## Unreleased

Improvement loop, rounds 1 to 4 ([PLAN-0002](docs/plans/active/PLAN-0002-improvement-loop-rounds-1-2.md)):

- Accuracy: a flat `ProducerDecision` output object (the `RootModel` declaration could never be satisfied through ADK's `set_model_response` on the LiteLLM route; live producer-dev went from 0/3 to 3/3); loader-free agents (the auditor is tool-less, the producer has only `read_file` and `list_files`, the procedure is preloaded, per-class references are selected by trusted code into the packet); the auditor rubric with rule ids `R1` to `R4`; a `provider_max_tokens` gate; a pre-model `target_binding` gate, derivation of a missing finding line from the recipe function, and binding of declared lines to the statement coverage reports; one time-bound policy (`request <= episode < activity`).
- Runtimes: a second Python recipe (`python.command_sentinel/1`) and one qualified corpus row each for JavaScript, Ruby, Java, Perl and C, each as a `Case.recipe` union member with its own trusted driver and image (`Settings.images`, `just images`).
- Evaluation and iteration: `corsair compare`, per-case and Markdown reports, the gate ledger (composed and isolated rows), `corsair runs`, `inspect --evidence`/`--explain`, `corsair explain`, `corsair dataset validate` / `replay-candidates`, `corsair intake`, `corsair agent preview`, `corsair doctor --model`, family/split checks, the `auditor-rubric` and `intake` datasets, `just live-agent` / `live-chain` records, `just settings-init` / `temporal-up` / `worker-up` / `demo`, `just toolchain`, and session-scoped Docker test ids.
- Review fixes on the PR: conservative coverage binding for skippable subexpressions, Perl undefined output holds, Java default-package coverage, one shared preparation path for prepare/verify/replay/preview, packet budgets that never cut required sections, dataset validation derives missing lines, consistent Perl baseline defaults.
- Organization (round 3): `entrypoints/terminal.py` is the `Terminal` class and the views live in `entrypoints/render/`, one module per view family; `Oracle`, `Dataset` and `DatasetEntry` are contracts and the dataset loaders live in `evaluation/datasets.py`; the Python driver sits under `adapters/sandboxing/drivers/python/` like the other runtimes and the recipes under `contracts/recipes/<language>.py`; `scripts/` holds the four operator scripts plus `scripts/benchmarks/`; corpus surveys live under `docs/reference/corpus/`. `corsair agent preview` reports episode request, LLM-call and tool-call counts; `just worker-up` attaches only to the dev server `temporal-up` started; `corsair dataset validate` rejects a demonstration label the scope policy cannot produce for the request's claim. The first live chain per runtime (Python, JavaScript, Ruby, Java, Perl, C) is recorded in PLAN-0002.
- Review response (round 4): clean negatives count distinct exploit payloads and are withheld for recipe kinds without a qualified auditor rubric; receipts are bound to their run, session and round; the final record survives a cancel; audit rules are the enum `R1` to `R4` and `ALL` bound to the decision; a C violation requires the sanitizer's exit status; private state and the artifact root are never admitted as source; import-time target lines are blocked before any model call; prepare heartbeats while blocked; human views print only code-owned text and label claimed versus evidence scope; `corsair dataset refreeze` replaces in-place repair and exits non-zero; a comparison across datasets is INCOMPARABLE.
- Latency and size: lazy CLI imports (`--version` 629 ms to 39 ms), snapshot reads once per listing (`list_files` 3.5 s to 28 ms on 991 files), the driver's in-process coverage report with `sys.monitoring` (per-role container 418 ms to 284 ms), worker slot settings; the dead DuckDB scorecard module and its dependency removed.

Evaluation gym ([PLAN-0003](docs/plans/active/PLAN-0003-evaluation-gym.md)):

- Telemetry: `Usage` records cached-input and thought-token totals plus per-call `ModelCall` and `ToolCall` entries (tokens, result bytes, truncation, seconds), capped at 64 each with `calls_truncated`, filled by the existing ADK callbacks and a new `after_tool` callback. Unreported counts stay `null`; saved results without these fields still decode.
- Runner: `corsair gym run TIER` (`just gym-run`) runs a frozen tier on an in-process production worker (`compose_worker`) and the existing `EvaluationWorkflow`, in the dedicated Temporal namespace `corsair-gym` on an ephemeral `temporal server start-dev` (or an existing server that already has the namespace; never `default`), on task queue `gym-<branch>-<sha7>`, and writes `report.json`, `trajectories.jsonl` and `scorecard.json` under `.runs/gym/<run-id>/`. `corsair gym score`, `gate` (exit 0/1/2), `replay`, `capture`, `export-grpo`, `budgets`, `ledger append|render` and `images`, with `just gym-gate`, `gym-replay`, `gym-capture`, `gym-ledger` and `images-gym`. See the [evaluation-gym guide](docs/guides/evaluation-gym.md).
- Images: gym runs tag each trusted image `corsair-<lang>:<7 hex>` from the working-tree content of `deploy/<lang>/` and its driver directory, build a missing tag with the `just images` build, and record image ids on the scorecard; the `:0.1` tags remain.
- Tiers: `evals/datasets/gym-tier0.json` (one case per language, 6) and `gym-tier1.json` (every runnable composed case, 15), entries copied verbatim from the existing manifests.
- Sandbox timing: each trusted driver adds optional `wall_usec` (around its native target step) and `cpu_usec` (cgroup v2 `usage_usec`, omitted when absent) to its receipt, and the Docker adapter adds `host_usec` (container create to wait); `RoleObservation` gains `wall_seconds`, `cpu_seconds` (driver-reported) and `host_seconds`, rebuilt from the receipt on saved-evidence re-validation and never used by any verdict, coverage or audit decision. Earlier results decode with `null` timing and still re-validate. The driver change gives every language a new content-tagged image, so gym runs after it carry a new configuration identity. Real Docker tests now run against the working tree's content-tagged images (`just images-gym`), never `:0.1`.
- Shared run store and candidate protocol: gym runs persist under `<main checkout>/.runs/gym/` for every worktree (`store/` for the content-addressed artifacts, `runs/<run-id>/` for run directories, `reference/` and `verify/`), unless settings name another `artifact_root`; each run directory adds `run.json` (sanitized invocation, git branch, commit and dirty flag, store, options and times) and `budgets.json` (the budgets bytes used); `replay`, `capture` and `score` read the store a run recorded. `corsair gym runs` (`just gym-runs`) lists stored runs newest first; `corsair gym verify` (`just gym-verify REFERENCE`) runs tier0, gates it, runs and gates tier1 unless tier0 was rejected, prints `VERDICT: …`, exits 0/1/2 and writes `verdict.json`. `corsair eval` and `gym run` share one row scorer, `evaluation.scoring.score_batch`.
- Reasoning markers: each gym trajectory adds `thought_share`, `output_cap` (from the frozen request's budget), `capped_calls`, `reasoning_cap_exhausted` and `dominant_call`; kind and language summaries and the scorecard add the mean thought share and capped-call and exhausted-cap episode counts, shown as columns by `render_scorecard` and as a per-language capped delta by `render_gate`. Optional fields only; reward, verified, objective and gate results are unchanged, and an existing scorecard decodes with the counts unknown.
- Run identity and operational stops: each gym trajectory adds `run_identity` (a new `RunIdentity` contract read from the stored result's `RunManifest`: package version, config, producer and auditor prompt, spec, output-schema and runtime-skills digests, risk-assessment and budget-policy digests, image id and models), `operational` and `operational_reason` (an `OperationalReason` derived only from code-owned gate-ledger gates and the workflow's activity-timeout reason); kind and language summaries add `operational_episodes` and the counterfactual `verified_accuracy_without_operational_failures`; the scorecard adds `run_identity` (every distinct value per component), `operational_episodes` and `operational_stops` (case, repeat, language, reason). `GateVerdict` adds `identity_changes` per component and `operationally_confounded_languages`, and the new reason `operationally_confounded` names a REJECTED gate whose regressed language would not regress had its operational episodes verified. `render_scorecard` lists the operational stops and `render_gate` prints an identity-changes line and per-language operational deltas. Reward, verified accuracy, J and every gate decision are unchanged; an existing scorecard decodes with the new values unknown.
- Smoke gate: `corsair gym gate --smoke` (`gate(..., smoke=True)`) still reports `objective_below_threshold` but decides only on language regressions, the token ceiling and the INCOMPARABLE conditions; `GateVerdict.smoke` and the view's `Gate (smoke)` header mark the result as a smoke result, not an acceptance. The default gate is unchanged.
- Ledger: `corsair gym ledger append` records an experiment without a scorecard (`--branch`/`--commit`), both tier gates in one row (`--tier0`/`--tier1` run directories or scorecards against `--reference-tier0`/`--reference-tier1`, default the latest baseline row of that tier, or `--verdict` with a new `VerifyRecord` contract), and the orchestrator decision (`--decision`, `--merge-commit` for merged). It refuses duplicate ids, a baseline without a scorecard and a merged decision without its commit. `LedgerRow` gains optional `tier0`, `tier1`, `decision` and `merge_commit`, and its scorecard metrics and `tier` become optional; recorded rows still decode and render identically. The Waves table shows branch@commit, both tier gates, ΔJ, token ratio and decision, and the rejected-ideas table lists rows decided `rejected`.
- Verify record: `corsair gym verify` writes `verdict.json` as the canonical `VerifyRecord` (one `TierGate` contract for verify and the ledger), which gains optional `decision`, `complete`, `skipped`, `reference`, `invocation` and `recorded_at`; `corsair gym ledger append --verdict` consumes that file directly. The earlier `tiers`-list shape of `verdict.json` is not read.
- Split check: `just dataset-families` also compares family stems (`<language>/<class>`, from the family id or the request's recipe kind, so `xxe` and `ih-java-xxe` collide), reads chain pairs in the `/v3/` and `-v3` request layouts, and flags source trees (same resolved path, pair stem directory or declared digest) shared across splits and labelled entries whose request is unreadable; it now reads each labelled entry's digest-verified request, never an oracle. The checked-in manifests still pass.
- Reviewed intake: `corsair dataset draft CHAIN_DIR… --recipe-template --split --out` assembles requests (corpus admitted in place), mechanical oracle proposals, a `corsair.dataset-draft/1` file no loader accepts and a code-owned `review.md`; `corsair dataset freeze DRAFT --review --into --against` writes only accepted or amended rows, refusing (exit 2) missing decisions, invalid rows, cross-split families or source trees and more than 64 entries, and exits 1 with the old and new dataset digests after writing. Recipe templates now bind any `Recipe` union member (`request_from_template`); an unknown kind is refused. No manifest, request or oracle was added.
- Intake split check: `corsair dataset freeze` builds each drafted row's family stem and source trees exactly as `just dataset-families` builds a frozen entry's (`families.request_member`), so a held-out draft sharing a tier row's family stem is refused with `family_stem_crosses_splits` and a tree shared with a `/v3/`-layout row is refused with `source_tree_crosses_splits`; freeze's separate tree-key rule is removed, and an other-split `--against` entry whose request is unreadable or changed is refused `against_unreadable`. `corsair dataset draft` takes the language from the recipe template's kind and drops a repeated leading language token, so the C rows under `chain/common/` draft as `ih-c-intoverflow-b` (family `ih-c-intoverflow`, stem `c/intoverflow`) instead of `ih-common-c-…`. No manifest, request or oracle changed.
- Staged intake: `corsair dataset draft … --source-root DIR` drafts chain directories and trees staged below an explicit staging root (such as `.work/intake/`), admitted relative to it with symlinks still refused; the draft records `source_root` and `staged: true`, and its review sheet adds `staged tree` and `licence file` columns. `corsair dataset freeze` on a staged draft requires `--import-into evals/datasets/corpus/<dir>`: for accepted and amended rows only it copies each tree byte for byte into `<dir>/<case id>/{source,fixed}/` with its licence and notice files, re-checks the snapshot digests, writes `provenance.json`, and freezes the requests over the imported trees; it refuses (exit 2, nothing written) a missing or out-of-corpus target, an existing target, a changed staged tree, and a tree without a licence file unless `--allow-noassertion` (recorded as `NOASSERTION`). Unstaged drafts are unchanged. No manifest, request or oracle changed.
- Run lock: `corsair gym run` and `gym verify` serialise on `<gym root>/lock/holder.json` (holder run id, pid, host, branch, commit, tier, start time; published atomically under an `flock` guard), taken after admission and before images or Temporal start and released on success, failure or Ctrl-C; `verify` holds it across both tiers. A waiter logs `gym.lock_waiting` with the holder every 60 s and exits 2 after `--lock-timeout` (default 2h); a holder whose pid is gone on this host is reclaimed with a `gym.lock_reclaimed` notice. `run.json` records `lock` (whether and how long the run waited, and for whom), and `wall_seconds` excludes the wait. `corsair gym runs` shows a held lock above its table; `corsair gym lock status` and `gym lock release --force` show and break it. `--no-lock` is for scripted tests only. This replaces the marker-file convention for overlapping live runs.
- Verify and score nits: `corsair gym verify` also writes its final `VERDICT: …` line to stderr in every output format, so a captured log shows it while JSON stays the only content of stdout. `corsair gym score` takes the run context from the run directory's `run.json` (which `gym run` now completes with the scorecard's `run` block), else the scorecard beside the report, else the new `--run-id`, `--git-commit` and `--git-branch`, else warns that it is unknown; a context recovered from the old scorecard is written to a missing `run.json`, so a run imported from before the shared store keeps its commit on rescore and in `corsair gym runs`.
- Target-side exception reward: a gym trajectory whose verdict is `ERROR` because every errored role's stored raw receipt shows a completed native run (driver record, junit `ERROR`, `observation_kind=execution_error`, bound finding line covered, cleanup confirmed, no `error` or `driver_error`) now scores 0 instead of -0.5, is never operational and stops at `target_exception`; harness and sandbox faults keep -0.5 and the kernel's `ERROR` verdict is unchanged. `Trajectory` adds `target_exception`, kind and language summaries and the scorecard add `target_exception_episodes`, the scorecard adds `target_exceptions` (case, repeat, language; new `TargetExceptionEpisode` contract), `load_results` returns `StoredResults` naming those runs, and `render_scorecard` and `render_gate` show the counts. Every other reward is unchanged; an existing scorecard decodes with the counts unknown.
- Gate tracks and sandbox faults: `gate(..., track="objective"|"accuracy"|"efficiency", target_language=None)` and `corsair gym gate`/`gym verify --track … [--target-language L]`. `objective` (default) is the previous rule unchanged. `accuracy` accepts when no language regressed, tokens stayed within 1.10× and macro verified accuracy rose by at least one case's majority in the language with the most cases (1 / (languages × its cases), from the baseline's counts) or the target language rose by one case; `efficiency` accepts when no language regressed, macro verified accuracy held and macro effective tokens or macro p50 seconds fell to 0.90× (seconds count only at equal recorded concurrency with no operational episodes). New reasons `accuracy_not_improved`, `accuracy_below_baseline`, `efficiency_not_improved` and the never-deciding `latency_not_comparable`; a smoke gate reports but never rejects on any track's improvement criterion. `GateVerdict` adds `track`, `target_language`, `delta_macro_verified_accuracy` and `seconds_ratio`; `VerifyRecord` adds `track`; `render_gate` names the track and its rule, and the ledger's gate cells name a non-objective track. A recorded role `ERROR` whose stored raw receipt has no driver record (for example `SandboxExecutionError`), or whose evidence bundle or receipt is missing, is now the operational reason `sandbox_fault` (`load_results` names those runs); target-side exceptions and payload-level `ERROR`s stay behavioural. Rewards, verified accuracy, J and the objective gate are unchanged; existing scorecards, verdicts and ledger rows decode and render as before.
- Identity: `Settings.identity` (and so each result's `config_digest`) no longer includes `temporal_address`, `temporal_namespace`, `task_queue`, `artifact_root` or `source_root`. This changes the configuration identity of every earlier run, including the recorded candidate diagnostics; none was promoted.
- ERROR observations: an `ERROR` `RoleObservation` keeps the receipt's recipe-module `covered_lines`, derives `target_executed` from coverage of the bound line as every other outcome does (it was always false), and carries a code-owned `error_kind` (`target_exception`, `harness` or `sandbox`) set from receipt facts only. No verdict, coverage gate, audit or kernel decision changes: any `ERROR` role still decides `ERROR` first and is never admitted on saved-evidence re-validation. Earlier results decode with `error_kind` `null`; no driver, image, prompt, schema of an agent output or budget changed, so the configuration identity is unchanged.

Initial pilot: two Google ADK agents (payload-pair producer, tool-less reject-only auditor) over a deterministic coverage-gated kernel that decides one of six labels in code, with each agent episode run as one Temporal activity.
