# Corsair pilot risk assessment

## Current v3 execution boundary

The user-authorized recipe-free path permits agent-authored test code and commands only inside the configured Docker sandbox. Canonical TestPlan limits, independent outcome-blind audit, read-only admitted source, non-root/no-network execution, bounded tmpfs/output/time/resources and immutable-ID cleanup apply. No target/test code runs on the host. Images must be locally available and operator-permitted; no model-owned pulls, builds, environment, mounts, credentials or security settings.

Native process receipts establish actual exits and output, not assertion truth or source exercise. Generated reports remain untrusted, and security assessment stays UNRESOLVED. Fixed-source reuse is a same-plan process comparison, not broad patch verification. Cancellation waits for bounded cleanup; exactly-once execution, host-loss continuation and hostile-source observation integrity are not established. Historical fixed-observer restrictions below continue to govern their retained v1/v2 diagnostics.

Owner: the Corsair maintainer. Execution class: durable; deployment tier: personal-use pilot, not production qualified. This assessment is included in the wheel and its digest is included in capability manifests.

The pilot accepts authorized source trees and concrete operator-defined secret-disclosure recipes for Python, dependency-free Node ESM and JDK-only Java static methods. Agents can read admitted source files and propose JSON payloads. They cannot author execution code, change fixed arguments, install dependencies, modify trusted tooling, choose a runtime, publish results, or close security findings.

Untrusted source and native target execution are confined to a dedicated disposable sandbox host. Docker uses an unprivileged user, dropped capabilities, no new privileges, network isolation, read-only source/driver/fixtures, and CPU/memory/process/time/output limits. These settings do not establish a universal malicious-code boundary. Prefer a qualified gVisor runtime or dedicated VM isolation when hostile source is admitted; do not share the host with secrets or production services.

Evidence risk: target code can be malicious and can interfere with an in-process native test/coverage mechanism. The observer is protected from model-written code by admitting only data payloads, but it is not attestation of an arbitrary hostile Python/Node interpreter or JVM. A target that detects the harness, edits its own process state, spawns uninstrumented descendants, or tampers with reporting requires a stronger observer recipe and must not be represented as universally verified. Runtime containment is independent of evidence authenticity.

Semantic risk: an auditor can falsely accept or reject. Its review is outcome-blind, fresh-context, and constrained by schema. It cannot authorize a result without admitted source evidence. Independent human-labelled auditor cases and whole-system evaluations are required before production use. Shared producer/auditor models have correlated failures.

Failed reproduction never means not affected. Application exposure remains conditional when only a component API is exercised. Fix results mean the submitted demonstration is blocked while the benign control remains valid, not that all related vulnerabilities or regressions are resolved.

Operational risks: a lost local artifact host loses retrievability; Temporal does not snapshot it. Interrupted/unknown operations reconcile committed manifests and are not blindly re-executed. Cancellation must stop and remove owned containers before the activity completes. Credentials remain in the worker environment, never in source snapshots or workflow arguments. Model/tool/round/time limits are hard admission bounds; token counts and cost may be unknown and are not claimed as exact pre-call financial limits.

Production/team use, privileged capabilities, remote publication, arbitrary probes, new evidence types, and new languages require a new assessment, affected conformance tests, human review of residual risk, and new capability identities. No automatic external approval or risk acceptance is implemented.

Raw native evidence requires a non-empty image identity equal to the admitted manifest image. Missing or mismatched image identity invalidates evidence; this does not establish generic hostile-source observation integrity.

The control role must confirm physical container cleanup before admitting the adversarial role. Unconfirmed cleanup stops the operation and remains explicit uncertainty, never a negative security verdict.

The native producer schema permits an explicit no-grounded-candidate decision. It cannot create an observation, refute a finding, claim a fix, or authorize publication. The model/recipe combination remains unpromoted until its separate live fixture and composed evaluation gates qualify it.

Terminal JSON is limited to 1,000,000 bytes. Optional diagnostics are capped with an explicit marker and exception chains are bounded at transport boundaries. Factual evidence and operation claims are not shortened; oversized structured results fail explicitly and may have no committed final-result receipt, while referenced native artifacts remain retained.

The declared outer probe timeout is forwarded to the trusted controller instead of a hidden 120-second cap. Controller supervision, coverage collection limits, isolated execution and immutable-container cleanup remain separate boundaries; a longer configured timeout does not grant broader sandbox permissions.

## Native procedural skill loading

The role-local procedure configuration admits reviewed installed-package SKILL.md text and references through native ADK loading only. The producer retains its two bounded source readers; the outcome-blind auditor gains only its own packaged procedure/reference loaders. No role receives a script runner, host code executor, environment, registry, remote skill discovery or additional network/source/target-execution permission. Always-on instructions and trusted evidence policy remain authoritative. Loader calls consume finite native episode budgets; successful loads are recorded separately from declaration. All admitted skill resources contribute to manifest capability identity and the existing immutable execution intent binding.

This is a changed prompt/tool/configuration identity requiring independent frozen producer/auditor diagnostics, real native consumer tests and a distinct composed live gate. Loading a procedure is not evidence that its reasoning is correct, and does not promote model quality, negative clearance, host isolation or production readiness. Missing usage/cost and loader/provider errors remain explicit.

Required role procedures are loaded by the native ADK parser during controlled factory assembly and supplied as instruction text before generation. Usage.skills_preloaded and agent.skill_preloaded record that actual preparation independently of optional agent-requested load_skill calls, which alone populate Usage.skills_loaded and consume tool calls. A model skipping optional loading does not omit the core procedure or become a claimed tool execution. This preload prompt identity supersedes the optional-loader-only diagnostic stage, whose zero-load results remain retained.

## Scoped paired outcomes and concrete language extension

New assessments distinguish a validated exploit demonstration from non-demonstration after completed bounded testing. NOT_DEMONSTRATED requires a healthy control and an actually executed, semantically valid non-violating adversarial observation with relevant native coverage and confirmed cleanup. It is not a not-affected statement or automatic issue closure. Missing execution/reports, rejected audits, unexpected errors and unfinished required work remain incomplete/operational. Legacy observations and labels are not rewritten.

Node admits an operator-selected dependency-free .mjs export and one inserted JSON payload. Java admits an operator-selected public static String method with String arguments; compilation and invocation remain in its reviewed offline image with annotation processing disabled. These are concrete component recipes, not npm/Maven/Gradle builds, TypeScript/framework support or hostile-interpreter attestation. Native report projection and exact image/procedure/schema identities must be qualified separately for each runtime and host. Model-authored assertions/code, target dependency resolution, network and credentials remain prohibited. Child-process coverage is not established.
