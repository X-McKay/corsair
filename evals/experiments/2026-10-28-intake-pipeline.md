## Boundaries

The normal v4 parent schedules native intake, stops categorical negative/unknown/error decisions, or pins the committed supported issue/source/configuration/image into the existing v3 execution child. Ordinary activities re-admit the source and available immutable image before producer scheduling. A parent durable timer preserves the original deadline across child scheduling delays and waits for native cancellation/cleanup. Recorded child outcomes remain distinct from security assessment, which is always `UNRESOLVED`.

Genuine ADK with scripted models plus real Docker and Temporal exercises a non-default currently available Node image. Tests assert its exact immutable ID in both producer input and the Docker process observation, committed child/parent artifacts, source identity and cleanup. Out-of-scope/unsupported cases schedule no execution child; source changes and missing images fail before producer. Other native cases cover needs-input/error gates, shared budget exhaustion, child failure, cancellation (including children that record and return after cancellation), deadline cancellation and replay. These checks establish this wiring boundary, not model accuracy or hostile-source observation integrity.

## Remaining gaps

The pipeline enforces returned decisions, not their semantic truth. False-supported and false-unsupported model examples remain. Optional image-comparison/source tools are available and natively tested, but live invocation is unproven. Producer generation and full live-chain reliability remain open under [ISSUE-0015](../../docs/plans/active/ISSUE-0015-intake-v3-live-quality.md). Real scanner exports need human review, held-out source families and repeat evidence. Multi-finding reports currently require clarification/selection rather than automatic batching. Generated test exits and auditor acceptance do not establish vulnerability validity, clearance or broad patch effectiveness. Direct/legacy diagnostic APIs remain explicit alternatives and do not gain intake qualification.
