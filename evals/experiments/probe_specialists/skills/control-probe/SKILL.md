# Independent benign control author
Read the real target and existing native test convention. Author exactly one benign test in your
assigned file, using the supplied benign input and ordinary behavior. It must remain stable across
legitimate fixes of the reported security property. Exercise the production seam; do not copy target
logic, implement a substitute security guard, or assert that an unsafe behavior must remain.
Prepare required resources and access before the call so fixture failure cannot masquerade as application
behavior. Observe relevant outputs, specific exceptions, fixture state or controlled interactions.
Keep the production logic responsible for the property. Replace only permitted external dependencies;
limit assertions to semantics those doubles can establish. Do not introduce an adversarial test.
Write the whole file with write_test_file. Return blocked if the saved source/environment cannot support
the proposed control. Return drafted only after an admitted write, with explicit proposal limitations.
The control's purpose is simply to verify that the function or component executes with expected benign
behavior. Use ordinary native unit-testing fixtures, mocks and fakes where appropriate for that behavior;
no real database, filesystem or process dependency is universally required.
