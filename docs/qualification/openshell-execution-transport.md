# OpenShell original transport-loss qualification

Date: 2026-10-11. **One actual original-forward transport-loss case passed on each of two fresh admitted nodes, with confirmed original cluster cleanup.** This is the original owned gateway-forward interruption case in [SPEC-0010](../development/specs/SPEC-0010-sandbox-execution-adapter.md) and [PLAN-0012](../development/plans/PLAN-0012-sandbox-execution-adapter.md), using the unchanged [execution adapter](openshell-adapter-execution.md).

## Fault and attribution

[The case](../../tests/qualification/test_execution_transport.py) starts one fixed bounded native command. It publishes an operation marker with actual remote PID/start ticks, then sleeps. An independent native observer confirms original remote execution before the fixture's original gateway-forward Popen is checked against PID/start ticks, UID/PPID and exact pinned argv, terminated through its supported object and reaped. No raw-PID signal or custom transport is introduced.

The actual native receipt must report `native_error`, failure layer `native_execution`, code `UNAVAILABLE`, unknown delivery/completion and no terminal exit. [gRPC Core's primary status table](https://grpc.github.io/grpc/core/md_doc_statuscodes.html) documents UNAVAILABLE for a TCP break after data transmission. A different RPC error, deadline, cancellation, resource or policy failure does not pass this oracle. The remote command is never replayed.

The original SDK worker must be reaped and its actual PID absent before reconnection. Only the supported native kubectl forward is recreated on the same endpoint and registered with the existing fixture. A reopened native client observes the original sandbox and remote process honestly, then existing lifecycle operations remove original resources/storage/tasks. Native client loss or host worker reap does not prove remote cancellation. All original/replacement forwards, gateway/private state and the original cluster must also be absent.
