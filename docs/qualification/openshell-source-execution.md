## Composition and authority

[The case](../../tests/qualification/test_source_execution.py) captures the exact committed five-file tree from a private bare Git fixture through GitSource, independently admits its manifest and five blobs through LocalArtifacts, stages separate files and runs one documented native directory upload. The fixture contains `.gitattributes`, `README.txt`, `nested/main.py`, `nested/input.json` and `nested/recipe.json`: 1,223 source bytes, all Git mode 100644, staging files 0400 and directories 0700. Its approved test-patch set is empty. Dependencies are Python stdlib only; there is no generated issue test, patch application or application-fix verdict.

Exact type, ownership, inventory, mode, size and digest checks precede one bounded native `python -B main.py` execution in the admitted staging directory. The immutable binding records captured commit/tree/manifest/blob references, recipe and input digests, actual Python executable identity, pinned workload image, effective policy hash/version, original sandbox ID, command digest, workdir and execution limits. Existing protected host execution intent/result and composition receipts preserve attribution.

Actual input `[1,2,3]` produces sum 6 and its input digest on stdout, plus a fixed stderr control. Terminal exit 0, exact bytes, original worker reap and unchanged relevant source observations are required. Completed bounded stdout/stderr enter separate immutable host artifact objects. After original sandbox cleanup, fresh host processes reread all source/binding and output references; authoritative source object identities/digests remain unchanged. Source reads retain the existing 4 MiB bound and output reads the existing 4,096-byte bound. The final composition result is written after these reads; the final result file itself is not independently reread by another process.

An operator diagnostic changes `main.py` after the successful unchanged-source execution. The verifier refuses the observed corruption before a second application dispatch; exactly one application execution intent remains. This diagnostic is not an issue-validation security assertion. Read-only staging permissions and pre/post checks do not detect every transient mutation: authoritative host inputs remain immutable outside workload reach under the accepted [execution contract](../execution-and-recovery.md).
