# Simplification, isolation testing, policy inspectability and generality review

## Problem and evidence

This is a whole-repository review at `32ef80e` (main, clean tree) requested by the user. It records findings and proposals only; nothing below is implemented, accepted or qualified. Method: one reviewer read every file under `src/`, `tests/`, `evals/`, `deploy/`, `policies/` and the design records; four delegated reviewers covered runtime code, the qualification harness and policies, the documentation and record process, and upstream behaviour of the pinned OpenShell 0.1.3, PydanticAI 2.55.0 and Temporal 1.34.0 releases (read from the tagged sources and the installed packages). Every finding cited here was checked against the file or installed package by the root reviewer; the offline suite was run first (`make test-config`: 255 passed).

Size facts that frame the findings:

| Area | Lines |
| --- | --- |
| `src/corsair` | 1403 |
| `tests/qualification` | 4215 |
| `tests/configuration` | 763 |
| `tests/unit`, `tests/agents`, `tests/temporal` | 1628 |
| Development records and handoffs (words) | about 65000 |

The qualification harness is three times the product code and the prose is far larger than both. Most of the proposals below move repeated harness and record content into a small number of typed, inspectable data files that the existing code consumes.

### A. OpenShell policy is not inspectable or modifiable in one place (highest impact)

- One checked-in policy exists: `policies/openshell/identity.yaml`. It equals the upstream default policy except `landlock.compatibility: hard_requirement`.
- At least seven further effective policies are built by mutating that dict in Python inside test modules: `tests/qualification/test_policy.py` (`fixture_policy`, four variants), `tests/qualification/test_toolchains.py` (`toolchain_policy` per language, and a four-endpoint `network_policies` block for dependency fetches). They are dumped to YAML in the evidence directory and passed to `openshell sandbox create --policy`.
- A second serialization path exists: `tests/qualification/test_lifecycle.py` turns the YAML into `sandbox_pb2.SandboxPolicy` by hand, renaming `filesystem_policy` to `filesystem` and dropping `network_policies` and `process`. Every adapter qualification runs under that spec. `src/` contains no policy code at all; the only production path from `policies/` to a sandbox is a test helper.
- No offline validation of the network-policy shape exists. A malformed or widened in-code policy fails only at live `sandbox create` (180 s budget). `assert_effective` compares the gateway's effective policy to the dict that was sent, so it proves fidelity, not restrictiveness. No guard checks `enforcement: enforce` or forbids wildcard hosts on the derived policies.
- Nothing enforces "operator-owned policies are not agent-editable". Source hashes are written into evidence after the fact but never compared with a committed pin.
- Upstream facts relevant here (OpenShell 0.1.3 docs, `docs/how-it-works/policies/`): the policy schema rejects unknown keys and duplicate keys; there is no `openshell policy validate` command and no published JSON Schema; the standalone `openshell-prover check <candidate> --boundary <boundary>` returns within-boundary, exceeds-boundary, error or unsupported and covers filesystem, landlock, process and REST endpoints with `enforcement: enforce`; `openshell sandbox get <name> --policy-only` prints the effective policy as clean YAML; the Python SDK has no policy API, policy travels inside `SandboxSpec` as the adapter already does. The repository's `docs/openshell-milestone.md` proposed `policies/openshell/{offline,qualification,dependencies}.yaml`, which never materialised.

### B. Generality: there is no unit of "case" in code

- `benchmarks/candidate-cases.json` (50 cases, provenance fields only) is read by nothing under `src/`, `tests/` or `evals/`. It has no field for test framework, discovery or run command, approved test paths, control and security test identities, expected per-revision outcomes, runtime image, dependencies or witness kind.
- The only executed case is a directory convention plus a shell recipe in prose (`benchmarks/fixtures/path-traversal/README.md`) and an ad hoc `recipe` dict inside `tests/qualification/test_source_execution.py`.
- The synthetic source exists twice byte for byte: `evals/issue_analysis/fixtures/{path_traversal,confined_source}.json` and `benchmarks/fixtures/path-traversal/{vulnerable,fixed}/documents.py`.
- Three incompatible revision identities are in use: Git commit and tree (`src/corsair/ports/artifacts.py`), SHA-256 of one file (the benchmark fixture), and URLs (`candidate-cases.json`).
- No bridge exists from a captured `SourceSnapshot` to `IssueAnalysisInput`. The two `SourceFile` classes share a name and nothing else. The agent's `read_source` is bound to in-memory fixture strings capped at 16 files and 64 KiB, so the agent cannot run over a real captured snapshot.
- `GitSource.capture` runs a full `git fsck --strict` and spawns two `prlimit`+`git` processes per blob inside a 20 s wall and 10 s CPU budget with a default of 128 files. The shortlisted real projects (JSPWiki, Cookiecutter) have thousands of files. `git cat-file --batch` over the `ls-tree -z` output is the native fix and keeps the raw-object guarantees the tests prove.
- `consume_test_report` requires `stdout` to equal the report bytes exactly and interprets native exit as `(0, 1)` with a pytest-shaped rule. pytest exits 2 to 5 for interrupted, internal, usage and no-tests cases; Maven returns 1 for both build and test failure; every real runner writes progress to stdout. No host-side JUnit XML reader exists although `native_report` in `test_toolchains.py` already parses JUnit neutrally and pytest, Surefire, jest-junit, rspec and prove all emit it.
- Toolchains are `if language == 'python'` branches throughout `tests/qualification/prepare_toolchains.py` and `test_toolchains.py` (base images, control commands, expected ids, cache extraction, wheel staging, network mode, read-only paths, per-language offline cases). A whole-tree hash means a Java fixture edit invalidates the Python image receipt. `test_recovery.py` fixes `PYTHON` so every adapter qualification runs only Python workloads.
- `evals/issue_analysis/live.py` `HypothesisSemantics` embeds the labels of one fixture as code regexes (`read_document`, `filename`, `documents.py` lines 3, 4 and 6). A second case or class needs code edits in a class named as if general.
- The two-test polarity rule (control passes on both revisions, security fails on vulnerable and passes on fixed) and the execution, finding and fix dispositions exist only in prose (`docs/investigation-contract.md`, SPEC-0018, the fixture README). Code encodes only "two distinct claims".

### C. Security scope and correctness

- `fixture_prompt` (`src/corsair/agents/issue_analysis/agent.py`) sends `inputs.model_dump_json(exclude={"source_files"})`, which includes `fixture_id`. The ids are `path-traversal-component-v1`, `instruction-injection-v1`, `missing-source-v1` and `component-variant-b-v1`. The live evaluator therefore tells the model the vulnerability class and whether source is missing before it reads anything, weakening exactly the injection and missing-information gates ISSUE-0007 depends on. The existing guard tests check only that source content and the oracle effect are absent.
- `IssueAnalysisExecution` (`src/corsair/workflows/issue_analysis.py`) copies `result.usage.input_tokens` and `output_tokens`, which `RunUsage` defaults to zero when a provider reports no usage. Missing telemetry becomes zero in the durable result. `evals/issue_analysis/live.py` already handles this correctly with `has_values()`.
- `OpenShellLifecycle` calls `wait_ready` and `wait_deleted` without `timeout_seconds`, so the SDK defaults (300 s and 60 s) apply; the lifecycle adapter has no operator-owned budget while the execution adapter has `ExecutionLimits`.
- `IssueAnalysis.status_matches_evidence` forces `unsupported` to carry `missing_facts`, so a model expressing an unsupported requirement must invent a missing fact.
- Operator budgets are literals in code: `tool_calls_limit=1` and `total_tokens_limit=5000` in the workflow while the input contract admits 16 files; the admitted qualification envelope is baked into `ExecutionLimits.__post_init__` and `SourceLimits.__post_init__`, so re-qualification needs a source edit and the port conflates type validity with the admitted range.
- Two `confined_path` implementations with different rules exist (`adapters/git_source.py` rejects `.git` components; `agents/issue_analysis/contracts.py` does not). Two consumers is the stated threshold for sharing.
- `adapters/git_source.py` imports `ArtifactStorageError` from `adapters/local_artifacts.py` although it accepts any `ArtifactStore`; the error type belongs in the port.
- `tests/qualification/test_test_report.py` carries no pytest marker and has no Makefile target, so the bounded report consumer's live test is only runnable by the ad hoc command in its qualification report. The Makefile default `CORSAIR_QUAL_RUN` is `.runs/network-<date>` for every target, so `make qualify-policy` without the variable writes policy evidence into a network-named directory.
- Supply chain is strong (every tool, manifest, chart, image and wheel pinned and verified; `uv run --locked`; actions pinned by SHA; chart render redacts secrets). Gaps: the Java toolchain image resolves Maven plugins from the network at build time and its retained cache manifest is never compared with a committed expectation; `prepare_toolchains.BASES` duplicates the Dockerfile `FROM` digests without a guard; `wheels.json` and `requirements.txt` duplicate hashes without a guard; `deploy/temporal/runtime-lock.yaml` is consumed by no code.

### D. Testing components in isolation

Done well: agents use `TestModel` and `FunctionModel` with `override_allow_model_requests(False)`; the provider is tested through a mock transport; artifacts and git capture are tested against the real filesystem and real git; activities use `ActivityEnvironment`; saved histories are replayed with `Replayer` and the same `PydanticAIPlugin`; the clock-driven `wait_service` guards and the parametrized "arbitrary failure cannot pass a control" guards test behaviour rather than mirror files.

Gaps:

- `native_worker` in `adapters/openshell_execution.py` combines host profile admission, SDK client lifecycle and event mapping. Unit tests replace the whole function, so output-budget slicing, unknown-event refusal and gRPC error mapping have no offline coverage, and the tests force the `fork` start method after pytest has started threads.
- `ReceiptDirectory` is constructed from a `Path` inside each adapter, so storage-failure paths are reached by patching private attributes, and the lifecycle adapter keeps a `_write` wrapper solely as a patch seam.
- Workflow failure branches (`workflows/fixture.py`) run only with `--temporal-address`; `make test-config` covers contracts and the direct composition only. Temporal's time-skipping environment is unused for the stated reason of no implicit downloads; the six inert histories already produced could be committed and replayed offline in CI with zero infrastructure.
- `tests/temporal/test_issue_analysis_support.py` builds the agent and `TemporalDurability` at import time, shared by two modules, and "direct mode" of `IssueAnalysisWorkflow` works only because `agent.run(model=key)` is resolved by the durability model registry.
- Pure helpers that are exercised only live: `bootstrap.download` checksum refusal (the supply-chain gate), `artifacts.storage_manifest`, `require_admission`, both `image_receipt` functions, `inspect_identity`, `assert_profile`, `collector_command` refusals and all of `qualify_artifacts.py`.
- Helpers are defined in test modules and imported across them (`test_readiness` to `test_recovery` to `test_policy` to `test_lifecycle`, and four more chains), so configuration guards import fixture-bearing live test modules to reach pure functions.
- `ExecutionReceipt` (a port type) carries six host-worker fields (`worker_glibc`, `worker_allocator_arenas`, affinity, pid, maxrss, limit flag) that any fixture or local adapter will leave empty.
- `agents/issue_analysis/agent.py` imports `TemporalDurability` for a type annotation, so every direct-mode import pulls `temporalio`.

### E. Simplification of the harness and Makefile

- Four implementations of the owned-sandbox lifecycle (create, identity check, wait, identity-checked delete, `wait_deleted`, resource and storage absence, `cleanup_confirmed`): `gateway.py`, `test_policy.py` (`owned_sandbox`), `test_recovery.py` (`owned`) and inline in `test_lifecycle.py`. Their teardown blocks are near-verbatim.
- Five identical two-line gateway gate fixtures (`policy_gateway`, `readiness_gateway`, `recovery_gateway`, `toolchain_gateway`, `adapter_gateway`); `TlsConfig` plus `OpenShellConnection` rebuilt in 13 modules.
- Receipt-writing subprocess wrappers exist five times (`deploy/kind/bootstrap.py`, `deploy/openshell/artifacts.py`, `tests/qualification/support.py`, `qualify_artifacts.py`, `gateway.py`), all writing the same `argv`, `started_at`, `exit_code`, `stdout`, `stderr`, `elapsed_seconds`, `timed_out` shape. Docker argv, private env, kind image load with content checks, cidfile control runs, deadline polling and port-forward restarts are each duplicated three to five times.
- Seventeen hand-maintained `*-source-hashes.json` path lists that already disagree about whether `pyproject.toml` and `uv.lock` are included.
- The Makefile has seventeen near-identical `qualify-*` recipes differing only in marker, `--tb=short` and `--network-evidence`.
- The `src/` state machines are long: `GitSource.capture` (about 85 lines, eight inline layer toggles), `OpenShellExecution.execute` (about 95 lines) and `LocalArtifacts.put`; a few duplicate assignments and a redundant in-loop prefix check remain.
- PydanticAI 2.55 accepts `retries={'tools': 0, 'output': n}`; the factory sets `retries=n` and then overrides the tool with `retries=0`.

### F. Documentation and record overhead

- Status is restated in at least six living places (README paragraphs two and three, three narrative paragraphs plus two tables in `CURRENT.md`, `Status:` paragraphs in `docs/implementation-plan.md` and `docs/openshell-milestone.md`, an appended section in `docs/benchmark-datasets.md`, every handoff's "Verified state") and is already stale: `CURRENT.md` says pytest PR #1 is awaiting publication while `git log` shows it merged at `32ef80e`.
- `docs/architecture.md` and `docs/openshell-milestone.md` describe `src/corsair/core/`, `composition.py`, `cli.py`, `images/`, four further agent packages and three policy files that do not exist, and omit `reports/`, which does.
- Records are near one-to-one spec and plan pairs; plans and issues have grown into journals (PLAN-0013 has twelve sections, eight beyond the template); 29 handoffs hold about 28000 words, including session-transient facts (private run labels, sub-agent role names, PIDs, branch names). The section-shape guard in `tests/configuration/test_development_workflow.py` enforces verbatim template headings for every record but checks none of the things that drift (latest handoff linked from `CURRENT.md`, design docs free of status lines, fused numbers such as "controls6/6" and "The50").
- Undefined jargon at point of use: "1A to 1F", "original-forward transport-loss", "operator-exclusive workspace", "fresh admitted nodes", three meanings of "admission", and over 1700 uses of "native".

### G. Done well and to preserve

Receipt discipline (exclusive intent and result files, fsync of file and directory, mode-checked private directories); tri-state delivery, completion and cleanup outcomes used and tested for every uncertain path; identity-checked cleanup and refusal to infer absence; raw-object git capture with hooks, filters and replacements disabled; explicit model, provider, model key, spec, workspace and limits with no silent fallback; citations that must match exact lines read in the current run; `extra="forbid"` contracts; oracles outside prompts and dependencies; the report consumer that binds trusted identities independently of untrusted claims and emits no disposition; native Temporal use (typed `ApplicationError`, per-activity retry policies, `REQUEST_CANCEL` child policy, replay on saved histories, one agent instance in both modes); a live policy oracle that compares base, full and revision hashes, loaded status, provider absence, OCSF event binding and server-marker absence; comprehensive pinning; honest qualification prose about estimates, unknowns and failed attempts.

### H. Native-feature audit: OpenShell 0.1.3, Temporal 1.34.0, PydanticAI and Pydantic Evals 2.55.0

Three further delegated reviewers compared every repository mechanism with the tagged upstream documentation and the installed packages. The root reviewer re-verified each item below by running or reading the installed package. Overall the repository uses the native lifecycle, execution, activity, retry, child-workflow, replay, test-model, output-validator, usage-limit and instrumentation features correctly and re-implements little. The gaps are mostly native features left unused and a few places where text is scraped although a structured field exists.

Re-implemented or duplicated where upstream already provides it:

- **Invented tool calls are retried, not refused.** `create_issue_analysis_agent` passes `retries=output_retries` as one integer, which sets both the tool and the output budget; the per-tool `retries=0` applies only to `read_source`. A model calling a tool that does not exist (for example `run_shell`) receives a retry prompt and the run can still complete with a valid output; verified against the installed package. The native form is `retries={"tools": 0, "output": output_retries}`, after which the same call raises `UnexpectedModelBehavior`, an attributable authority-expansion attempt. The records describe tool retries as zero, so the experiment metadata is also wrong. Such attempts produce no tool span and are invisible to every span-based evaluator; count them from captured messages.
- **Local provider labelled as OpenAI.** `provider.py` composes the vLLM endpoint with `OpenAIProvider` plus a hand-built profile. The installed `pydantic_ai.providers.vllm.VLLMProvider` supplies the inline-definitions schema transformer and the single-system-message setting natively and labels responses and spans as vLLM; four prompted-output overrides that the live evidence requires stay as a `profile=` merge. Passing an explicit client keeps the no-environment-fallback rule.
- **Evaluation metrics typed twice.** `evaluate.py` and `live.py` increment `native_requests` and token metrics that Pydantic Evals already extracts from chat spans (values identical in the fixture report), and hand-type experiment metadata (limits, retries, profile flags) that the upstream guide names as the duplicate-configuration anti-pattern. Derive metadata from one frozen configuration object. Note that zero-valued `increment_eval_metric` calls are dropped, so a measured zero is indistinguishable from unrecorded; record zeros as attributes.
- **Gateway logging activation scraped from log text.** `test_policy.py` regexes "Setting changed" and "OCSF JSONL logging toggled" lines; the gateway exposes `configuration_admission.config_revision` on `sandbox get -o json`, which the supervisor reports only after applying settings. Poll that field instead.
- **Global policy absence parsed from stderr.** `global_policy_observation` matches error wording; `openshell policy list --global -o json` is structured.
- **Error classification from code plus raw status JSON.** `GatewayError` carries `error_info` (reason, domain, metadata), `retry_delay` and `field_violations` as attributes; receipts record only `code` and the raw status. Record the typed reason and classify on it, never on message text.
- **Redundant empty-ID guard** in `OpenShellLifecycle.create`: the SDK already raises `SandboxError` on an empty id.
- **Workflow inputs as three positional parameters.** Temporal drops type hints when the payload count differs from the parameter count, which is what produced the recorded dict-shaped inputs and three timed-out runs. One typed request dataclass carrying inputs, model key and budget is the documented form and records the budget in history.

Native features available but unused, in rough priority:

- **Durable request admission.** `CreateSandboxRequest`, `DeleteSandboxRequest` and `ExecSandboxRequest` all carry `request_id` (verified in the installed protobufs); the gateway replays successful outcomes and answers `REQUEST_OUTCOME_UNCERTAIN`, `REQUEST_STREAM_UNAVAILABLE`, `REQUEST_REPLAY_UNAVAILABLE` or `REQUEST_ID_PAYLOAD_MISMATCH` on a resend. The curated SDK never sets it, so this needs a narrow generated-stub seam inside the adapter, used for reconciliation only, never automatic retry. It would distinguish a gateway-generated exit 124 from a confirmed remote one and confirm a lost create or delete against the original UUID. Limits to qualify first: a per-caller cap of one thousand unresolved admissions that never expire, fingerprints bound to gateway key material, and no replica takeover. This is also the narrow native candidate for small-file transfer that ISSUE-0006 says does not exist: exec with bounded stdin plus `request_id`.
- **Gateway metrics already exposed.** The pinned chart enables `service.metricsPort: 9090` by default; snapshots of `openshell_server_grpc_requests_total` and relay counters before and after each case would replace many "internal RPC/poll/retry unknown" entries in the qualification reports.
- **Provisioning and condition fields** on `sandbox get -o json` (deadlines, admission start, driver operation pending, conditions such as supervisor not connected) give the readiness attribution ISSUE-0004 lacked; `image_preparation_timeout_seconds` lets the gateway assign the timeout reason itself.
- **Implicit chart and runtime defaults.** `deploy/openshell/values.yaml` still uses the deprecated `allowUnauthenticatedUsers` and `workspaceStorageClass` aliases and does not pin `sandboxUid`/`sandboxGid` (source default 10001, documented default 1000), `policyValidationFailureMode` or `restart_policy`. Pin them explicitly and assert the rendered gateway configuration.
- **Policy advisor posture.** Policy drafts are created in every sandbox regardless of advisor state and a global automatic approval mode would auto-approve them; pin `agent_policy_proposals_enabled=false` and `proposal_approval_mode=manual` after install and retain pending drafts as denial corroboration.
- **Policy prover and `--policy-only`** as offline and live guards (see A above). Landlock "ruleset built" events in workload logs give per-sandbox evidence of applied paths.
- **Temporal SDK metrics in process** via `Runtime(telemetry=TelemetryConfig(metrics=MetricBuffer(...)))`: schedule-to-start latency, task failures and request failures are exactly the rows the reports mark unknown.
- **Offline replay regression.** `Replayer.replay_workflows(histories, raise_on_replay_failure=False)` needs no server; committing small inert fixture histories guards workflow, PydanticAI and temporalio upgrades in `make test-config`. `WorkflowEnvironment.start_local(dev_server_existing_path=...)` performs no download, so a pinned CLI can serve an opt-in developer path; the operator-owned service stays the qualification gate because the ephemeral server exposes no process identity.
- **Server-side run bounds, memo and explicit identities.** `start_workflow(execution_timeout=...)` closes timed-out qualification runs instead of leaving them running; `memo` carries case, mode, digest and prompt version; explicit `@workflow.defn(name=)` and `@activity.defn(name=)` plus a recorded worker build id freeze the replay contract.
- **Adapter activity design before Milestone 3.** Temporal's `CancelledError` derives from `Exception`, so the broad `except Exception` in `OpenShellExecution.execute` would turn a cancellation into a failure; the adapter needs progress and cancelled callbacks (no-ops in direct mode), attempt-scoped receipt names, and Temporal timeouts ordered strictly above the adapter budgets. Output bytes of up to one megabyte belong in the artifact store, not activity payloads. The delivery tri-state and host receipts stay application-owned: Temporal records delivery to a worker, not to the gateway.
- **PydanticAI details.** Pin `InstrumentationSettings(version=5)`; pass `run_id` and `metadata` to `agent.run` so receipts, spans and histories correlate; describe the `path` tool parameter (its schema has no description); filter `ToolReturnPart` by `outcome == "success"` in the output validator; move model settings to the model so direct, evaluation and durable runs share them; add a `prepare` hook that withholds `read_source` when no source exists; use `Dataset.evaluate(repeat=n)` with `case_groups()` and a report evaluator for the consistency denominator. `LLMJudge` stays excluded until a pinned judge is calibrated against reviewed outputs and reported as a supplementary score.

Legitimately application-specific and to keep: fsynced host intent and result receipts (no native client journal; gateway receipts hold no output), the host execution worker limits (no per-exec output cap or memory bound exists natively; the SDK retains every chunk), the 74 and 124 handling, identity pre-checks and immutable cleanup confirmation, CNI fence probes, the admission preflight (which depends on undocumented `copy-self` and `capability-probe` internals and should be labelled so), source confinement and current-run citation grounding, attempt receipts and provider-usage coverage, and the exclusions of `FallbackModel`, transport retries, workspaces, approval tools and online judges.

## Proposal and limits

Ordered work packages. Each is bounded, uses upstream capabilities first, and is independently testable offline. None is authorised by this record; each would get its own spec or plan when selected.

1. **Policy profiles with a typed loader, pin and lint.** Move every effective policy into `policies/openshell/<profile>.yaml` (identity, canary-control, canary-restricted, toolchain-python, toolchain-java, dependencies-python) with a small `parameters` block for the fixture hostname and address. Add `src/corsair/adapters/openshell_policy.py`: one pydantic model mirroring upstream schema v1 with `extra="forbid"`, `to_proto()` for the SDK path and `to_yaml()` for the CLI path, replacing the hand-written rename in `test_lifecycle.py`. Pin profile digests in `deploy/runtime-lock.yaml` and verify before every create so an agent edit fails closed until the lock is changed in a reviewable diff. Offline guards on the models: landlock hard requirement, every endpoint `enforce`, no wildcard hosts, `allowed_ips` as single addresses, canary paths never writable. Add a committed boundary policy and run `openshell-prover check` as an offline guard (any result other than within-boundary fails; keep paths identical to avoid unsupported). Add `make policy-show NAME=<sandbox>` wrapping `openshell sandbox get --policy-only` diffed against the rendered profile. Cost: one model, six data files, two Make targets; removes about 150 lines of in-test mutation.

2. **Small correctness fixes.** Exclude `fixture_id` from `fixture_prompt` and assert its absence; rename fixture ids to opaque values. Make durable usage honest: `int | None` token fields or a `usage_reported` flag derived from `has_values()`, plus `output_corrections` counted from `RetryPromptPart` and `elapsed_seconds` and `mode` on the execution result. Add `LifecycleLimits` and pass explicit timeouts. Allow `unsupported` without `missing_facts`. Move admitted envelopes out of port constructors into an explicit operator configuration object recorded in receipts; accept a frozen `IssueAnalysisBudget` input in the workflow. Share one `confined_path` and move `ArtifactStorageError` to the port. Use the `retries` dict form. Add the `test_report` marker and Make target and a guard that every live module has exactly one slice marker with a target; fix the Makefile default evidence directory.

3. **A case schema and host-side report reader for generality.** Introduce `benchmarks/cases/<case_id>/` with `case.json` (identity, language, scope, two revisions each as git ref or inline path plus digest, toolchain key, frozen test artifact digest, control and security test ids, optional witness kind, provenance by reference to `candidate-cases.json`), `agent-visible/issue.md`, `evaluator/oracle.json` (expected per-revision outcomes plus the existing issue-analysis oracle fields, and the live rubric constants now embedded in `live.py`) and `tests/`. Add `deploy/qualification/toolchains/<id>/toolchain.json` (image digest, discovery and run argv templates, JUnit report path, runtime identity probe, offline cache manifest, diagnostic cases) consumed by `prepare_toolchains` and `test_toolchains` as data. Add one host-side JUnit XML reader producing the existing `WorkloadTestReport` shape from a bounded collected artifact (the already qualified untrusted-file path) instead of exact stdout equality, with the runner exit convention part of the toolchain descriptor. Add a `PairVerdict` model that takes the vulnerable and fixed admitted claims and discovered counts and yields `fix: verified` only under the contract's polarity, with any skip, unknown delivery or count other than two yielding `not_verified`. Start with the existing synthetic pair and deduplicate its source between `evals/` and `benchmarks/`. A new language then costs one Dockerfile, one toolchain descriptor and one case directory; a new class costs one case directory with a different witness kind. No case or language branches in core code or prompts, consistent with the continuation rules in `docs/benchmark-admission-progress.md`.

4. **Bridge captured source to the agent.** A `SourceReader` protocol (`list()` of paths with line counts, `read(path, start, end)` returning `SourceExcerpt`) with the existing in-memory implementation and an `ArtifactStore`-backed one over `SourceSnapshot`. Replace per-blob `git` processes with one `git cat-file --batch` fed from `ls-tree -z`, and replace full `fsck` with the per-object digest check already performed (or `--connectivity-only`). Keep `FixtureDependencies` small because Temporal copies deps into every activity payload with a 2 MB cap.

5. **Harness consolidation without losing attribution.** One `admitted_gateway` fixture yielding `TlsConfig` and `OpenShellConnection`; `tests/qualification/sandboxes.py` with one owned-sandbox context manager parameterised by creator (CLI, SDK, adapter) owning teardown and the `cleanup_confirmed` accounting; shared `receipts.py`, `waits.py` and `forwards.py` for the duplicated wrappers (deploy scripts import from a `deploy/common.py`, not from tests); `record_sources(evidence, name)` hashing the modules actually imported under the repository root plus declared data files; an `evidence_summary` context manager that always writes a default-failed summary; a Makefile pattern rule with a marker to network-requirement table. Move cross-imported helpers into support modules so guards stop importing live test modules.

6. **Isolation seams in `src`.** Inject `ReceiptDirectory` (or a narrow write protocol) and delete the `_write` wrapper; extract `stream_execution(client, pipe, ...)` from `native_worker` and test it in-process with a fake client; inject the worker target and multiprocessing context; nest host-worker fields under `host_profile` in the receipt; move the `TemporalDurability` annotation behind `TYPE_CHECKING`; build the test agent in a fixture rather than at import; commit the six inert fixture histories and replay them offline in `make test-config`; add offline tests for the pure helpers listed in D. Later, when a second agent arrives, add in-memory fakes for the three ports and consider `pydantic.dataclasses` for the port value objects.
