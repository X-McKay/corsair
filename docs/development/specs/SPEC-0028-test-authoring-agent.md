# Test authoring agent and native pytest runner

## Goal and scope

Implement agent 4 of [IDEA-0004](../ideas/IDEA-0004-end-to-end-agent-plan.md) and its deterministic companion. Given a ready [SPEC-0022](SPEC-0022-test-planning-agent.md) plan, the saved inventory and the same environment evidence, the agent writes exactly the two planned native tests into approved test paths and shows, through capped development runs, that both are discovered and run. It emits a frozen-ready `TestPatch` or an honest `BlockedAuthoring`; never a finding or fix. The runner adapter applies an approved patch to a fresh baseline workspace, runs native pytest discovery, executes once and returns per-test outcomes and bounded failure classification from actual JUnit XML, plus SPEC-0017 `AdmittedTestClaims` bound to the JUnit artifact.

Excluded: a live sandbox workspace (source delivery under SPEC-0025 and approved test-file delivery are the gating nodes), the frozen per-revision execution node, Maven/Surefire, durable registration, witness capture outside the test process, live-provider qualification and connection to any other stage.

## Boundaries and design

**Ports.** `ports/test_runner.py` is vendor-free: `ApprovedPatch` (one to four files, each in the operator's approved set, order-independent SHA256), `TestWorkspace` (`prepare` a fresh sandbox holding baseline source plus exactly this patch; `release` it and report confirmed or unconfirmed cleanup), `TestRunner.run`, and result types `Discovery`, `Execution`, `TestCaseResult`, `FailureDetail{kind, type, path, function, line, message}` and `NativeTestRun{failure_layer: workspace | discovery | execution | report}`. No OpenShell workspace adapter exists yet; this is the blocked live node.

**Runner.** `adapters/pytest_runner.py` composes `TestWorkspace`, the existing `SandboxExecution` port and `ArtifactStore`. The operator-owned `PytestRunnerConfig` holds the argv prefix, JUnit path and absolute workspace root. Discovery runs the plan's discovery tokens plus the patch paths and requires a complete receipt, exit 0 and exactly the two planned node ids. Execution uses a fixed POSIX `sh -c` wrapper whose stdout is exactly the JUnit file and whose exit status is pytest's, with `--tb=native`; node ids and paths are positional arguments, never script text. JUnit bytes from a complete receipt are always stored. `reports/junit.py` refuses oversize, non-UTF-8 and any markup declaration before parsing, requires exactly the expected testcases, and classifies the innermost frame inside a patch test file. Workspace release always runs; nothing is retried. JUnit stays a workload claim: it supplies classification input for the SPEC-0027 gates, not attestation.

**Agent.** `agents/test_authoring/` follows the stage layout: factory with explicit `Model`, `PROMPT_VERSION`, `CONFIG_VERSION`, optional `TemporalDurability`, content-excluded instrumentation, zero tool retries; skill `write-native-tests` delivered eagerly through native `Capability`. Tools: the shared windowed `read_source`; `write_test_file(path, content)`, refused outside the approved paths (ending the run, as for invented reads); `run_tests()`, which applies the current files through the injected `TestRunner`. The patch is rebuilt from this run's successful write calls in message history rather than held in mutable dependencies, so the tools stay correct when native durability serializes deps. `AuthoringBudget` is operator-owned: development runs (default 3, range 1–5) and `reveal_security_outcome` (default false). Runs beyond the budget return `not_run` and execute nothing. By default a run shows discovery, collection errors and the control outcome; the security test's outcome is `withheld` unless it is a JUnit setup error, which says nothing about the assertion.

**Contracts.** `TestAuthoringInput{plan: ReadyTestPlan, source_files, environment}` refuses a plan whose discovery tokens differ from the environment, unapproved planned paths, test ids that are not plain node ids in their planned file, and approved paths that would overwrite saved source. The model-facing draft is `AuthoredPatchDraft{status, security_assertion_lines, limitations}` or `BlockedAuthoringDraft{status, layer, reason}`. The trusted output function assembles `TestPatch{files, control_test_id, security_test_id, discovery_command, run_command, patch_sha256, security_assertion_lines, dev_runs, limitations}` from this run's own writes and runs. It refuses a patch without a current-run run, whose last executed run does not cover the final files, that misses a planned path, whose final run did not discover exactly the two planned ids or whose control did not pass, whose security test had a setup error or skip, where either planned test function is absent or has no assertion, or whose declared security assertion lines are not assert or `pytest.raises` lines of the security function. `BlockedAuthoring` retains the last files and runs. Layers are compile, discovery, dependency, fixture, sandbox and unknown.

`security_assertion_lines` serves SPEC-0027's `ExpectedFailure.assertion_lines`: with the plan's `security_expectation` and the security test's path and function, the gates can require that a baseline failure is the planned assertion. Trusted code verifies the lines are assertions of the right function; it cannot tell a required-behavior assertion from a fixture precondition, so that choice remains a reviewed model claim.

## Acceptance and validation

Deterministic tests with `FunctionModel` and real requests blocked: reference patch assembled from current-run writes and runs, with no fixture id, labels or quotations in the prompt; writes to application source, test configuration, traversal or absolute paths end the run before any execution; refusal of no run, write after the final run, non-assertion lines, verdict fields and a missing planned function; patch refused but blocked admitted after collection error or failed control; operator run budget; withheld versus revealed security outcome; previous-run history authorizes nothing; input refusals; AST static checks flag mocks, skips, swallowing excepts, constant asserts and a missing target call. Runner unit tests use fake ports and the real local artifact store, plus one real pytest run of the reviewed SPEC-0018 bytes per variant, and one composition test drives the agent through the real runner over those reviewed bytes. Native Pydantic Evals: six frozen development cases, two repeats, scripted runner, reporting status, run count, contract, assertion lines, static semantics, read-before-write, write-before-run and withheld security separately.

Model-authored test code never runs on the host. The reviewed SPEC-0018 bytes run locally only in tests that assert byte identity. None of this is live qualification: the scripted runner replays fixed observations, and a live evaluation needs the OpenShell workspace adapter, the local provider and independent review of actual patches.

## Decisions and open questions

Defaults chosen where the plan forked: the security outcome is withheld except setup errors; patch state lives in message history; approved test paths may not overlap saved source, so editing existing test files needs a separate decision; Python AST is the only static analyzer, matching the pytest-only runner; the runner refuses parametrized node ids. The runner emits no typed witness. IDEA-0004 and SPEC-0027 require the witness to be captured outside the test's own pass/fail claim, while everything this runner reads (JUnit, captured stdout including the SPEC-0018 audit-event lines) is produced inside the test process and stays a workload claim; parsing a witness from it would relabel a claim as evidence. A witness therefore needs its own operator-owned capture (for example sandbox or policy telemetry, or an operator-installed observer whose output the workload cannot write) delivered beside the run, which is open work for the execution node, not this adapter. Node ids and failure paths are relative to the workspace root, which the workspace adapter must make the repository root so they stay repository-relative. Open: the workspace adapter needs the in-sandbox absolute root for frame paths; large captured output can exceed the 256 KiB JUnit bound and yields `invalid_report`; JUnit lives in the workspace, so test code can rewrite it, consistent with treating it as a claim. The plan is [PLAN-0027](../plans/PLAN-0027-test-authoring-agent.md).
