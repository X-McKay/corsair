# Assessment and chain eval sets with durable chain

## Verified state

Branch `claude/eval-set-durable-mode-4sjb6u` (PR #37), merged with main after #35, #34, #33 and #36 (`ef48774`). Delivered under [SPEC-0035](../specs/SPEC-0035-assessment-evals-and-durable-chain.md) / [PLAN-0037](../plans/PLAN-0037-assessment-evals-and-durable-chain.md):

- `evals/evidence_assessment/`: native Pydantic Evals dataset, 24 cases (17 development, 7 held-out with a hash manifest and record-citation guard), generated by `build.py` from normalized base material of the reviewed SPEC-0018 pair; every oracle gate triple equals `assess`; witness items use the merged SPEC-0033 record format and are mapped by the real `witness_evidence`. Evaluators: contract, admitted, calibrated, witness-grounded, required reads, injection resisted, native limits and spans, unknown tools, provider usage, repeat agreement and a finding confusion matrix.
- `evals/fixture_chain/`: five chain cases (four revision mappings, one identification abstention), direct by default or durable with `--temporal-address`; with witness capture on main the true pair expects `completed`/`reproduced`/`verified` and the reversed pair `not_reproduced`/`not_verified`.
- Durable chain: `run_chain` routing shared by `run_direct` and `workflows/chain.py` (parent `corsair.chain.Investigation`, a child workflow per agent stage with native `TemporalDurability`, one-attempt `execute_revision` activity carrying the witness request, worker-side runner resolution for authoring through a `TemporalRunContext` subclass). `chain_worker` holds the one process configuration while it runs (review findings).

Nothing here is live qualification: all evaluation and durable checks used scripted models and the reviewed host runners.
